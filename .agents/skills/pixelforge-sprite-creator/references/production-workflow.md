# Compact production workflow

Use CLI JSON reports, not whole-file raster reads. `inspect FILE` defaults to bounded summary; choose one of --animation NAME, --frame ID, --layer ID, --game, --palette or --frames. Summary also pages layer identifiers. --limit defaults25 (max100), --offset pages lists. Source bytes and counts describe scale; parsing still loads the full canonical source locally.

`contact FILE --animations idle,walk --columns 4 --scale 4 --background checkerboard --output preview.png` creates labeled image plus preview.contact.json with full identifiers and rectangles. --prefix walk- and --start/--end are optional conventions/ranges. Review limit1000cells/64MP; split larger sets. Labels show source IDs, entry indices and milliseconds. Actual visual review is mandatory for appearance tasks when available; otherwise disclose structural-only evidence.

`diff BEFORE AFTER --summary --preserve-frames approved-id --preserve-layers base --preserve-game` asserts agreed invariants and returns bounded changed frame/layer/pixel-count/bounds/palette/sequence/timing/game/anchor summaries. Palette-only recolor can leave pixel indices unchanged. Shared-source warnings identify propagation; duplicate and retarget before isolated edits. Do not treat intended redesign as an accidental preservation violation.

`check FILE --contract CONTRACT` uses explicit task expectations. Example: `{"version":"1.0","requiredAnimations":["idle"],"animations":[{"name":"idle","layerPhases":[{"layer":"aura","minDistinctPhases":2,"minVisibleEntries":4}]}]}`. Only require aura coverage when the task specifies it. requiredLayers, requiredAnchors, explicit durationsMs, optional action/direction coverage, baseline/bounds/empty warnings and reasoned exceptions are available; discover the installed semanticContract.schema.json. Reports separate structuralErrors, semanticViolations, visualWarnings and intentionalExceptions. Warnings alone do not fail; structural/contract violations exit1. No aesthetic guarantee.

For many assets, retain source documents under assets-src/, batches/inputs alongside them, runtime exports under public/assets/generated/, review reports under previews/ and temporary files outside source. Version1.0 asset manifest: `{"version":"1.0","assets":[{"id":"hero","source":"assets-src/hero.sprite.json","output":"public/assets/generated/hero","layout":"atlas","runtimeKey":"hero","operations":["assets-src/hero.ops.json"]}]}`. Paths are relative to the manifest and cannot escape. Optional inputs are hash-tracked generator inputs, never shell commands. `build-assets --manifest pixelforge.assets.json` hashes source/batches/inputs/options/tool version, verifies output hashes and skips fresh assets. Changed managed outputs rebuild through staging. Modified/unknown user files cause refusal, never silent deletion.

Re-export with `export FILE --format phaser --output DIRECTORY --replace`. Only bundles with a valid .pixelforge-bundle.json receipt and unchanged owned bytes can be replaced. Legacy bundles without receipts need a separate new output path; preserve old assets until integration is verified. Sibling backups permit rollback on observed failure; interrupted publication may leave a backup/lock requiring review. No multi-directory transaction or power-loss guarantee. Do not use rm -rf as the normal update procedure.
