# PixelForge v0.5 implementation plan

Target: software 0.5.0, preserve document/game formats 1.0. No commits, push, publication, credentials or unrelated global changes. The source tree was clean at audit start (HEAD 0c0acc4). The seven original feedback reports are absent from docs/feedback; the supplied brief is the evidence source, not independently verified agent transcripts.

## Baseline and reproduction

Inspect root/package manifests and lockfile, TypeScript configurations, core/CLI/exporters/Phaser implementation, build/pack scripts, skill, examples, documentation and tests. Run typecheck and regression suite in place. Copy tracked files to an isolated temporary directory outside the repository, with no dist or node_modules, and run npm ci then typecheck/test/build/pack. Keep execution evidence in v0.5-verification.md. A source snapshot is equivalent to a clean clone for generated-artifact independence, but does not prove remote publication or Linux execution.

## Execution and acceptance gates

0. Audit/plan: record baseline/reproductions; distinguish reports from confirmed code behavior.
1. Distribution: fix source resolution, clean snapshot runner, package version/manifest/checksum production and CI.
2. Engine/export: managed replacement and adversarial rollback tests; exact-version Phaser investigation/consumers.
3. Inspection/discovery/contact: bounded summaries, authoritative operation help, label/map export and tests.
4. Production: semantic checks/diff/preservation, palette/diagnostics and incremental manifest builds.
5. Skill/docs: implement only real commands, update root entrypoint and progressive references.
6. Integration: independent Phaser3/4 consumers and generated large workload; benchmark small/medium/large inspect/output/render/export/contact/memory/incremental behavior.
7. Release: full original/new suites, clean build/pack, artifact integrity/install/TS/browser checks, security audit and complete requirement matrix. Label candidate if required work is incomplete.

Initial measurable targets (record actual measurements, no invented percentages): default inspection JSON <=32KiB on a generated 80-frame/many-layer/many-animation source; selected lists <=100 entries by default and <=1000 explicitly; 64MP output ceiling and contact cell cap; unchanged asset rebuild performs no render/write; every packed consumer has no workspace/sibling dependency or omitted declaration target. Runtime budgets are measured rather than promised across machines. Source parser memory remains proportional to canonical file size.

Each stage updates v0.5-progress.md and this plan with deviations, executed tests and pending items. Platform execution is Windows-only until another platform actually runs; CI configuration alone is not execution evidence.
