# Phase 3 requirement evidence

Software v0.3.0, document format 1.0, game extension and bundle contracts 1.0. No migration required. This audit maps the original Phase 3 brief to implementation and executed verification; final command results are recorded in verification.md.

| Requirements | Implementation and evidence |
| --- | --- |
| 1–3: preserve foundation and separation | Original 46 tests retained. Core has no Phaser/React/DOM/filesystem/Sharp imports. Separate packages/phaser declares Phaser ^3.90 peer. Browser and Node share core rasters and bundle assembly. |
| 4–6: versioned metadata, bodies and regions | schema/game.ts validates origin, rect/circle, named scoped hit/hurt regions, anchors and events. Project refinement validates namespace, canvas bounds and references. game-metadata and game-bundle tests cover compatibility, invalid bounds/references, precedence, disabled regions and transforms. Body remains project-stable. |
| 7–8: timing and events | Phaser registration uses namespaced keys, repeated references, full per-entry duration overrides and repeat -1/0. Real smoke times 120/220/180ms playback transitions. Observer deduplicates entry transitions, replaces listeners and cleans on destroy; unit tests cover repeat/start/complete. Entry associations remap during structural edits, unsafe deletion rejects. Skip policy documented. |
| 9–10: fixed sheet and native atlas | Shared sheet preserved. renderAtlas emits untrimmed native JSON Hash, deterministic shelves, padding/POT/max limits and empty source cells. Atlas tests reconstruct pixels; real Phaser loads both generated layouts. Repeated animation entries share source textures. |
| 11: bundles and publication | assemblePhaserBundle validates cross-file references and returns PNG raster plus native atlas/PixelForge game/animations/manifest/README. Node stages files and renames new directory, rejects existing output. Tests verify cleanup/preservation, safe names and CLI export. Platform constraints documented. |
| 12: typed adapter | Loading, cache validation, registration, character creation, body configuration, play, active boxes and events are distinct APIs. Typecheck and unit tests plus real Arcade scene. |
| 13,17: web metadata and exports | GameData edits origin, bodies, scopes, box geometry, events and anchors through history. GameOverlay separates geometry from pixels, with toggles/snapped drag/resize. PhaserExport exposes layout/name/padding/max/POT/includes and summary. Game editor smoke verifies history, movement/resize, save/reopen and browser/Node export equality. |
| 14: agent batches | Version1.0 operations extended with origin/body, shared GameBox kind API, events and anchors. Clone/final validation unchanged. Playground batch authors animations/combat data; metadata batch tests verify failed operations preserve source. |
| 15–16: playable generated example | examples/phaser-playground uses Phaser/TS/Vite, loads generated atlas and sheet, idle/walk/jump/attack, gravity, ground/platforms, movement/flip, target and F3 debug. Real smoke moves/jumps, checks body offsets and circle/origin, triggers valid timed hit and toggles debug. Scene draws actual computed Arcade/combat geometry. |
| 18–19: tests/reliability | Existing tests plus metadata, atlas, bundle, adapter, CLI and real browser suites. Allocation checks precede buffers; deterministic source order; no PNG encoding during ordinary canvas updates. Atlas summary raster recomputes only when project/options change. |
| 20–23: documentation/delivery | All requested reference documents updated; Phaser integration, atlas, collision, pipeline and this audit added. CLI and demo commands executed. Final report states actual outcomes and bounds. No GitHub push. |

Deliberate limits: no trimming/rotation (source offsets remain exact), world combat boxes reject sprite rotation, Arcade circles should use uniform positive scale. Entry events are structured data and fire on observed transitions; skipped/unobserved entries are not replayed. Browser bundle downloads are multiple files. Existing CLI bundle directories are not replaced. Optional ZIP/body presets are not included. Game-specific movement remains solely in the example.
