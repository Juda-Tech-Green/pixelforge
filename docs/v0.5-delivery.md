# PixelForge0.5.0 candidate delivery

## Improvements and resolved feedback

Clean workspace TypeScript builds now resolve source independently of generated declarations. CLI discovery and selective summaries avoid agent context floods; contact PNG/maps provide labeled review. Task-defined semantic checks, bounded diffs and preservation assertions support targeted edits. Custom palettes and detailed coordinate failures improve drawing ergonomics. Receipted staged replacements remove the normal destructive re-export workaround. A lightweight manifest hashes inputs/options/tool version and rebuilds only stale managed assets. Setup/AGENTS/skill and local release integrity are unified.

Reported problems A–K now have implemented behavior and Windows regression/integration evidence; L has tested optional anchor/static synchronization helpers and integration guidance. Exact external game visual defects cannot be reproduced without its absent source/reports. Feedback analysis distinguishes those reports from confirmed source behavior and generated reproductions.

## Already working / architecture

The deterministic renderer, version1.0 format, frame independence, shared CLI/editor raster model, atomic project apply, cross-field validation, untrimmed sheets/native JSON Hash atlases, Phaser3 timing/events and protected skill installer already worked and remain intact. No new bitmap representation, cloud service, database, gameplay framework, audio/3D scope or editor redesign was added.

Relative TypeScript paths affect workspace compilation only; emitted package imports remain bare names and packed exports/declarations point to dist. Analysis stays in platform-independent core; Node filesystem/staging/contact/build logic stays in exporters/CLI; engine concerns stay in Phaser. Schemas for asset manifests and semantic contracts are new independent version1.0 documents, not a sprite-format migration.

## CLI and skill

Added/extended: inspect --summary/--animation/--frame/--layer/--game/--palette/--frames with pagination; operations list/describe; contact; check --contract; diff --summary and preservation flags; init --palette; export --replace; build-assets --manifest. Strict setPixel remains strict and shape clipping remains unchanged. Shared-source edits emit bounded apply/diff warnings. Commands and limits are documented in cli-reference.md and the focused guides.

The concise skill now follows Discover → Inspect → Specify → Generate/Edit → Render → Review → Validate → Export → Integrate. Progressive references explain dense-file avoidance, targeted invariants, actual previews, task-defined effect requirements, host-engine detection, safe managed exports and distinct evidence levels. Environment reporting inspects the installed adapter's peer range; installed-file lifecycle/compatibility regression is covered. Autonomous host activation was not re-executed.

## Distribution and engine compatibility

Four local0.5.0 tarballs contain compiled code/declarations/licenses/readmes and core schemas. SHA256SUMS, versioned notes and verify-release detect corruption/invalid entries, not publisher identity or provenance. Portable setup copies archives inside the consumer and uses online dependency resolution normally; cached offline mode is explicit. Direct Zod dependencies are declared by importing packages. No namespace ownership or publication is implied.

One adapter supports the tested common APIs on exact Phaser3.90.0 and4.2.1. Independent installed consumers compile the actual adapter source and run WebGL loading for atlas/sheet,100/200ms nonloop playback, origins, rect/circle bodies, hit/hurt geometry, anchors, nonuniform scale/flips, marker/completion restart semantics and static synchronization. Screenshot pixels confirm visible sprite rendering. Other versions in the caret range were not individually tested. Rotation-free combat boxes, directly transformed sprites (no parent Containers), positive unrotated static scaling and uniform static circles remain documented bounds.
