# Reusable agent prompts

Explicitly request “Use the pixelforge-sprite-creator skill” when host discovery is uncertain. For every workflow keep source JSON and operation batches, validate using `pixelforge validate FILE`, render with `pixelforge render FILE --animation NAME --frame 0 --output frame.png`, and export a contact sheet using `pixelforge export FILE --format spritesheet --output sheet.png`. Use the local installed bin or `node node_modules/@pixelforge/cli/dist/index.js`; no public registry installation is implied.

| Scenario and prompt | Expected outputs | Objective success criteria |
| --- | --- | --- |
| **Animated coin:** Create a 16×16 gold coin spinning through six frames with transparent backgrounds and consistent shading. | coin.sprite.json, construction.ops.json, six-frame PNG sheet and manifest | 16×16 source frames; six ordered spin entries; transparent zero; explicit timing; visually distinct turning widths. Validate source and inspect contact sheet. |
| **Walking character:** Create a 32×32 pixel art adventurer with eight walking frames at 8 FPS and a four-frame idle animation. | character.sprite.json, batches, walk/idle previews, sheet | Eight walk entries at125ms, four idle entries, stable baseline/palette. Render each animation and verify counts through inspect. |
| **Reference:** Inspect the attached character reference and recreate its essential silhouette and colors as an editable 48×48 sprite. Generate idle and walk animations. | reference path/rights notes, sprite-spec.json, editable JSON, batches, contact sheet | Only visible features claimed;48×48 grids and explicit durations; visual comparison recorded or unavailable-vision limitation disclosed. Run skill project consistency helper. |
| **Phaser combat:** Create a 64×64 knight with idle, walk, jump and attack animations. Define collision body, hurtbox, and timed sword hitboxes. Export a playable Phaser bundle. | knight.sprite.json, metadata batch, native atlas bundle, scene integration | All four animations; validated in-canvas stable body; entry-scoped attack activation; target response only in valid overlap. Run validate-export helper with source and actual browser game test. |
| **Existing correction:** Open the existing PixelForge project. Fix the left foot in the third walking entry without modifying unrelated frames, then validate and export. | updated.sprite.json, focused edits batch, before/after previews | Resolve zero-based entry2; duplicate source first if shared; all unrelated pixel planes/entries preserved. Compare JSON and rasters, validate and render corrected entry. |
| **Full integration:** Inspect this Phaser repository, generate a new enemy character with two animations, export its assets, register its animations and load it into the existing scene. | source/batches, asset bundle in project conventions, loader/scene change | No unrelated overwrite; both named animations load, no runtime asset errors, timing/physics if requested verified. Run target's build/tests plus real game check. |

For Phaser bundles use `pixelforge export FILE --format phaser --layout atlas --name hero --output NEW_DIRECTORY`. Validate with `node PATH_TO_SKILL/scripts/validate-export.mjs NEW_DIRECTORY FILE`. Warnings are review prompts, not proof of visual defects. Report toolchain checks separately from any real agent-host discovery test.
